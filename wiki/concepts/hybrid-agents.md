# Hybrid Agents

## Definition

A hybrid agent is an LLM agent architecture that combines two processing modes — a **reactive layer** for fast, stimulus-driven responses and a **deliberative layer** for explicit goal reasoning and planning — with a routing mechanism that determines which mode handles each incoming task. The core design question is: when does an agent react immediately vs. deliberate?

This architecture answers the dual-process question structurally rather than relying on prompting or post-hoc metacognition.

## Relationship to Dual Process Theory

Hybrid agents are the engineering instantiation of Kahneman's System 1 / System 2 distinction:

| Dual Process | Hybrid Agent | Fast Task | Slow Task |
|--------------|-------------|-----------|-----------|
| **System 1** (fast, automatic) | Reactive layer | Pattern match, tool retrieval, status checks | Heuristics, instinct |
| **System 2** (slow, deliberate) | Deliberative layer | — | Planning, decomposition, multi-step reasoning |

The routing mechanism (the "when to deliberate" question) is itself a decision that could be made reactively or deliberatively — creating a bootstrapping problem that most implementations solve with a simple heuristic (task complexity estimate, token count, explicit flags).

## Architectural Decomposition

### Reactive Layer

The reactive layer implements the ReAct loop: observe → think (minimal) → act → observe. It handles:
- Tool calls with known arguments (low uncertainty)
- Routine sub-tasks generated by the deliberative layer
- Status checks and monitoring tasks
- Simple branching decisions where the path is obvious

The reactive layer is fast because it doesn't maintain an explicit goal representation — it responds to the current context with the next action.

### Deliberative Layer

The deliberative layer uses an explicit world-model to simulate outcomes before committing to action. It handles:
- Task decomposition (given a high-level goal, break it into sub-tasks)
- Planning under uncertainty (when the path to the goal is not obvious)
- Replanning (when observed state diverges from expected state)
- High-stakes decisions (routing to reactive layer would be insufficient)

The deliberative layer maintains a goal hierarchy and can inspect, revise, and share its plan state.

### Mode Switching

The routing mechanism determines which layer handles each task:

```
Task arrives
    ↓
Complexity estimation
    ↓
┌─ simple/routine ──→ Reactive Layer (ReAct loop)
│
└─ complex/uncertain ─→ Deliberative Layer (Planner)
```

Complexity estimation can be:
- **Explicit**: Token count, explicit complexity scoring, domain-specific heuristics
- **Implicit**: LLM decides whether to invoke planning based on its own uncertainty assessment

Critically, the deliberative layer itself generates the sub-tasks that the reactive layer executes. The reactive layer is never truly autonomous — it's always executing sub-plans generated by the deliberative layer.

## Failure Modes

1. **Routing brittleness**: If the complexity estimator makes systematic errors, the agent either over-deliberates (wasting compute on simple tasks) or under-deliberates (fails on complex tasks by routing them to the reactive layer)

2. **Deliberative layer plan quality**: The deliberative layer is only as good as its world-model. A poor world-model produces plans that fail when executed.

3. **Reactive layer execution errors**: The reactive layer executes sub-tasks generated by the deliberative layer. If the decomposition is wrong, the reactive layer executes the wrong tasks correctly.

4. **Bootstrapping the routing decision**: The routing decision itself could be made reactively or deliberatively — creating a meta-level recursion that most systems avoid with a fixed heuristic.

## Connection to MOP

In the [[concepts/maximum-occupancy-principle]] framework, hybrid architecture corresponds to **Layer 1 (Goal Inference and Intent Alignment)** for the deliberative path and **Layer 0 (Intrinsic Motivation)** for the routing decision. The reactive layer handles routine goals that don't require layered processing.

The [[bounded-rationality]] concept explains why the routing exists at all: cognitive resources are bounded, so the agent must decide when the marginal value of deliberation exceeds its cost.

## Open Questions

1. **Optimal routing criteria**: What is the best signal for mode switching — token count, explicit complexity scoring, LLM self-assessed uncertainty, or something else?

2. **Planning depth vs. reactive accuracy tradeoff**: Deep deliberation improves plan quality but increases latency. Is there a Pareto frontier for task complexity vs. planning depth?

3. **Learning the routing policy**: Can the routing decision be learned from task success/failure data rather than fixed heuristically?

4. **Multi-agent hybrid patterns**: When multiple agents collaborate, does each agent maintain its own reactive/deliberative split, or does the coordination mechanism itself implement a hybrid pattern?
