# 2606.05828 — Statistical Priors for Implicit Preferences: Decoupling Skill Selection as a Local Harness in Personal Agents

**Authors:** Gan, Zeyu · Tang, Huayi · Liu, Yong
**Submitted:** 2026-06-04
**Link:** https://arxiv.org/abs/2606.05828
**Full text (ar5iv):** https://ar5iv.labs.arxiv.org/html/2606.05828

## Abstract

Local personal agents over remote LLMs + a growing external-skill library. The paper proposes a **lightweight local preference harness that decouples statistical preference learning from semantic intent parsing** — local stats *modulate* (don't replace) the remote LLM's skill-selection decisions. Reports lowest cumulative regret and highest test accuracy vs. memory-augmented agents.

## Core Idea

The architecture separates two layers:

1. **Local statistical layer** — runs lightweight bandit/preference learning on observed outcomes (skill picks, user signals). Cannot do semantic reasoning, must stay cheap.
2. **Remote semantic layer** — the big LLM does intent parsing and skill selection, but is *conditioned* on the local stats (priors over which skills are likely good).

The decoupling is the contribution: the local harness does *not* try to understand the user semantically. It just accumulates statistical evidence and biases the LLM's selection. This avoids the cost of running a full model locally while still giving the system a personalization signal that improves over time.

## Why It Matters for This Stack

- **Local harness** maps directly onto the [[meta-harness]] pattern: an evolvable local component that runs beneath/alongside the main LLM and shapes its behavior.
- **Skill selection** over an external library is exactly the [[hermes-skills]] problem.
- **Decoupled statistical from semantic** is the same layering pattern used elsewhere in this codebase — keep the cheap, fast, statistical layer separate from the expensive, slow, semantic layer.
- The "modulates, doesn't replace" framing is a useful contrast to architectures that try to make the local layer do too much (e.g. local RAG-as-replacement vs. local stats-as-prior).
