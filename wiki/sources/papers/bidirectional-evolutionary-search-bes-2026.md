# Self-Improving Language Models with Bidirectional Evolutionary Search (BES)

**arXiv**: [2605.28814](https://arxiv.org/abs/2605.28814) | May 27, 2026  
**Authors**: Guowei Xu, Zhenting Qi, Huangyuan Su, Weirui Ye, Himalindu Lakkaraju, Sham M. Kakade, Yilun Du (Harvard + MIT)

## Core Finding

**BES** — bidirectional search that couples forward candidate evolution (recombination operators that escape model distribution) with backward goal decomposition (dense sub-goal verification). Proves that expansion-only candidates are confined to a narrow entropy shell; evolution operators can escape it.

## Two Fundamental Limitations of Prior Methods

| Limitation | Tree Search / Best-of-N | BES |
|-----------|------------------------|-----|
| **Sparse verification** | Binary/coarse feedback | Backward search decomposes into checkable sub-goals → dense feedback |
| **Distribution confinement** | Candidates only via autoregressive expansion → confined to high-probability regions | Evolution operators recombine parts of different trajectories → reach low-probability correct solutions |

## Forward Search: Evolution Operators

Four operators inspired by sexual reproduction:
1. **Combination**: merge strengths of two distinct responses
2. **Translocation**: splice segments between responses
3. **Deletion**: remove least sound segment
4. **Crossover**: exchange gene segments to produce novel combinations

**Theorem**: Candidates generated by expansion-only search are confined to a narrow entropy shell; evolutionary operators can escape it.

## Backward Search: Goal Decomposition

Recursively decompose original task into checkable sub-goals:
- Produces dense intermediate feedback to guide forward search
- Theorem: backward search can exponentially reduce required samples to find a correct answer

## Results

| Setting | BES vs Baselines |
|---------|-----------------|
| Post-training (logical/multi-hop reasoning where GRPO/MaxRL/Tree-GRPO fail) | Consistent improvement; baselines degrade or fail |
| Inference (3 open problem solving benchmarks) | Outperforms OpenEvolve, GEPA, ShinkaEvolve in average and best-case |

## Key Insight

> Static skill injection doesn't always work — skill usefulness depends on task fit, requiring adaptive management.

Extends to search: static expansion doesn't always work — candidate quality depends on distributional fit, requiring evolutionary recombination.
